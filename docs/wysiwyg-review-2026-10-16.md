## 本轮修复

1. **列表编号与结构**：写回读取每个 `ol` 的起始编号；回车按光标所在项续号；拆分使用最内层文本容器；同一列表项下所有子列表都参与序列化。
2. **代码内容保真**：不再删掉代码末尾换行，解决末尾回车无效；正确拆分 CRLF；闭合围栏必须与起始围栏使用同种字符且长度足够。
3. **块菜单操作与撤销**：插入段落、删除块、替换源码前先同步待写回文字；撤销可恢复操作前刚输入的内容。
4. **复杂块保护**：根据解析 token 检查真实嵌套结构，不能完整序列化的嵌套引用、含复杂块的列表/引用、多段落列表项使用只读渲染，通过块源码窗口修改。
5. **快速撤销回归**：独立审查发现第一次渲染优化会在 React 合并更新时漏掉规范化；已增加脏块独立渲染版本，保证源码恢复后 DOM 同步恢复，并保留旧快照不可变性。

## 性能结果

| 场景 | 修改前 | 修改后 |
| --- | --- | --- |
| 80 段正文，编辑一段后切换焦点：发生 DOM 子树变更的块数 | 80 | 1 |
| 64,888 字符、12,000 块（含空段落）的合成文档分块，中位耗时 | 8,643 ms | 39 ms |

分块测量在同一台机器、同一 Node 环境运行，预热一次后测五次取中位数；该结果只衡量分块函数，不代表完整编辑器启动或每次交互耗时。并发构建期间曾测得约 73 ms，说明耗时仍受系统负载影响。

实现改动：空段落行号使用已有行索引二分定位；块组件使用稳定回调及每块渲染版本，避免一次编辑触发整篇规范化；HTML 缓存保留 600 项上限，超限只淘汰最久未使用的条目。

## 保留的限制与后续重点

- 表格方向键尚未接入跨格导航；目前主要依赖 Tab/Enter 和鼠标。
- 下划线行内标记和复杂嵌套格式尚未纳入即时转换，多光标仍使用源码模式。
- 图表与块级公式、上述复杂列表/引用仍通过块源码编辑；编辑表面没有校对高亮。
- 方向键跨块仍以源码偏移边界判定，未覆盖所有视觉软换行场景；列表精细层级调整还需要更完整的交互验收。
- 本轮未运行 Tauri 安装包验收，也未使用真实 Windows 中文输入法逐项手动操作；组合输入验证使用自动化合成事件。

下一轮宜优先完善表格方向键与复杂列表编辑，并保留本轮的源码保真、立即撤销、邻块 DOM 不变三个回归约束。

# 编码、字号、字间距与图标改进

本记录补充同日的代码优化与舒适界面改进，说明最终操作入口与验证范围。

## 操作入口

| 功能 | 使用方法 | 默认值或范围 |
| --- | --- | --- |
| 界面字号 | 设置 → 外观 → 界面字号 | 默认 13 px，11–20 px |
| 字间距 | 设置 → 外观 → 字间距 | 默认 **0.6 px**，0–5 px，步长 0.1 px |
| 正文字号 | 设置 → 外观 → 内容字号 | 与界面字号独立，原有设置继续保留 |
| 文字编码 | 点击桌面应用状态栏右侧的编码名称 | 新文档默认 UTF-8；已打开文档记录实际编码 |
| 文档切换 | Ctrl/Cmd+P 或标题栏文档按钮 | 按名称、路径搜索已打开的文档 |

字号与间距即时预览，取消时恢复原值；保存后写入桌面配置和启动缓存，刷新/重启后继续使用。旧配置自动补入 13 px 与 0.6 px。Monaco 使用原生 letterSpacing 选项，预览标题、段落、代码和 AI 正文使用同一字间距设置，避免编辑器字符测量与显示错位。

## 编码行为与文件保护

支持 UTF-8、UTF-8 with BOM、UTF-16 LE/BE（各含无 BOM 与带 BOM 两种）、GBK、GB18030、Big5、Shift-JIS、Windows-1252，共 11 个选项。

- **选择保存编码**：当前文字保持不变，下次保存按所选编码写入；编码变更会标记文档未保存。
- **用编码重新打开**：读取磁盘并重新解码，文档有未保存修改时禁用；读取期间发生编辑或文件变化时拒绝覆盖。
- 自动识别 Unicode BOM 与有效 UTF-8；无法确定的旧编码、含空字节的无 BOM 文本请求用户选择，不以错误编码替代字符。
- 旧编码不能表示的字符会阻止保存并显示原因。先编码再原子写入，转换失败不会截断或污染原文件。
- 取消编码读取后，迟到结果和错误不会添加标签、覆盖内容或重新打开选择窗口。
- WebDAV/S3 历史恢复保留原始字节；打开旧编码云端版本也提供解码选择，不再将其显示为空白文本。

编码窗口支持方向键、Home/End、Tab 焦点循环与 Esc 关闭；简体、繁体和英文界面沿用项目翻译机制。文件读写及字节解码在 Rust 桌面后端执行，浏览器验证使用内存示例与测试 IPC。

## 图标

界面图标集中到 24×24 的几何图标库，共 125 个轮廓；工具栏、资源管理器、文件类型、设置、状态栏、AI 指令、窗口控制与弹窗采用统一线条。用途由轮廓与文字提示共同表达，文件类型继续保留类型标签和颜色。

根据最新反馈，**AI 助手恢复为原来的双星样式**，侧栏、状态栏、设置、工具栏与对话入口一致使用该轮廓。

应用图标使用用户提供的“深蓝渐变折叠白色 Z”原图，保存为 `src-tauri/icons/app-icon.png`，未重新绘制。原图与项目源图 SHA-256 一致：

```text
cbacfba48172ee55adc17d3ade095fa5ea0ed42442e1599ce36fdddbd8d34454
```

Windows ICO、macOS ICNS、桌面各尺寸 PNG、Android/iOS 资源、启动标识、标题栏和 favicon 均由该原图生成。再次生成使用 `npm run icons:app`；Markdown 文件关联图标使用 `npm run icons:markdown`。

## 验证

- 前端 430 项测试通过；Rust 171 项通过，3 项依赖本地外部 CLI/代理环境的测试保持忽略。
- ESLint、TypeScript/Vite 构建、Rust 格式检查通过。
- 编码测试覆盖全部 11 个选项的往返、BOM、GB18030 Emoji、非法 Unicode、不可表示字符、原文件保护、保存/读取竞争、云端版本选择与取消。
- 独立 Edge 会话验证即时预览、取消恢复、保存后刷新、编码键盘操作、未保存文档保护、英文编码窗口、12 种主题配置及 900/960/1100/1440 px 布局。
- 18 px/1.2 px 组合及 20 px/5 px 最大组合均检查布局无横向溢出；预览标题和 Monaco 字间距分别验证。
- 图标在 16 px 下逐个渲染检查，图标画廊检查几何边界。
- 性能回归：连续 20 次编辑的历史写入为 0；撤销、任务勾选、模式切换与关闭保护通过。最终入口 JavaScript 约 948 kB，编辑器内核作为约 3.80 MB 的异步包加载。

复现命令（项目根目录）：

```powershell
npm test
npm run lint
npm run build
# 启动独立开发服务器后执行浏览器检查
npm run dev -- --host 127.0.0.1 --port 1425 --strictPort
node scripts/verify-editor-settings.mjs
node scripts/verify-editor-ui.mjs
node scripts/verify-editor-performance.mjs
```

在 `src-tauri` 目录执行 `cargo fmt --check`、`cargo test`。浏览器脚本依赖 agent-browser，Windows 默认使用 Edge。

Windows release 构建已通过 `npm run tauri -- build --no-bundle`，产物位于 `src-tauri/target/release/zeditor.exe`；该构建嵌入本轮前端资源及新图标。相邻的 `zeditor_mcp_server.exe` 为 MCP 辅助程序，复制应用时一起保留。先退出旧实例再启动新程序，以免单实例机制将操作转发给正在运行的旧版本。

验证范围为 Windows 编译、Rust/前端自动测试与 Edge 交互；真实付费 AI、实际云服务器及 macOS/Linux 桌面运行未作端到端验证。当前安装的软件需更新构建产物后才能使用这些修改。

# 云备份（WebDAV / S3）

Zeditor 支持在本地保存成功后，**自动**把文档备份到你自建的 WebDAV 服务器或 S3 兼容对象存储。配置在 `设置 → 云同步`，**两者可同时启用**，各自独立队列与状态。

::: tip 本地优先
云端备份失败**不影响本地保存**——文档永远先落在你自己的磁盘上，云端只是副本。
:::

## WebDAV 备份

1. 开启「启用 WebDAV 自动备份」；
2. 填写：服务器地址（如 `https://example.com/dav`）、用户名、密码 / 应用密码、远端根目录（默认 `/Zeditor`）；
3. 点「测试连接」验证凭据。

::: warning 凭据安全
WebDAV / S3 凭据仅保存在本地设备，不会上传到任何第三方服务。
:::

## S3 兼容存储备份

支持 AWS S3、阿里云 OSS、腾讯云 COS、华为 OBS、MinIO、Cloudflare R2 等：

1. 开启「S3 云同步」；
2. 填写：服务端点、存储桶、地域、Access Key / Secret Key、远端根目录（默认 `/Zeditor`）；
3. 自建 MinIO 等未开虚拟主机域名服务时，开启「Path-Style 路径风格」；
4. 点「测试连接」验证。

远端根目录会在桶内路径最前方应用一次。例如设为 `/Zeditor`，对象键以 `Zeditor/工作区/文档.md` 开头，不会重复成为 `Zeditor/Zeditor/...`。修复前已存放在双层目录中的备份会保留在原处，不会自动删除。

## 版本策略

- 每次本地保存成功后自动在后台入队上传；
- 保留**最新文档副本 + 最近 20 个不同内容版本**；文档与引用附件的 SHA-256 共同决定版本，单独更换图片也会形成新版本；
- Markdown 图片、链接、引用式链接及 HTML `src`、`href`、`poster` 中指向文档同级 `.assets/` 的资源随版本上传，包括 `@[video](...)`、`@[audio](...)`；
- 附件先上传，全部成功后才发布版本清单；附件缺失或不可读时报告失败并保留重试任务，不会显示完整备份成功；
- 失败任务持久化，应用重启后自动恢复上传。

## 查看与恢复

- **状态栏**实时显示同步状态，点击可重试；
- 「**浏览全部备份**」打开历史对话框，按时间列出各版本；
- 新版本显示「完整备份 · N 个附件」。选择「恢复到新文件夹」，指定父目录后，应用会建立独立的 `zeditor-restored-…` 文件夹，保留原文件名、原始编码字节及 `.assets` 相对路径；
- 「打开」也会先恢复完整文件夹，再从磁盘打开文档，图片和媒体可离线读取；
- 文档与每个附件均在写入前校验 SHA-256，附件还核对大小。缺失或被篡改的远端附件会阻止恢复；
- 每次恢复都使用新文件夹，不覆盖当前文稿或现有附件。意外写入失败会提示错误；已创建的部分恢复目录会保留供检查；
- 旧历史版本仍可打开或另存原始文档，明确显示「旧版：仅文档」。旧备份中未上传过的附件无法补回。

## 附件范围与限制

附件备份限于文档同级 `.assets/` 内、被文档引用的普通文件；不会上传未引用附件、任意绝对路径、其他本地目录或网络链接。Markdown 代码块中的示例链接不作为附件。发现其他目录的本地图片、媒体或附件引用时，会明确报错并保留重试任务；请先复制进 `.assets` 并修改引用。其他笔记的 Markdown 链接保留原样。远程 URL 不会下载，若希望离线使用，请先把资源复制进 `.assets` 并更新引用。

单个附件最多 128 MiB，每份备份最多 1024 个附件，文档和附件总计最多 512 MiB。超限会明确报告失败。路径穿越、符号链接、Windows 目录联接、保留设备名及跨平台大小写冲突会被拒绝。

备份沿用文档已选择的编码解析引用；对无法确定编码的旧任务，若无法可靠解析附件，应用会要求按正确编码重新打开并保存。恢复始终保留原始文档字节。

远端“最新文档副本”是便于查看的单个文件；完整离线还原应使用应用内的历史版本恢复。附件按版本保存在历史目录中，与该版本一同清理。

# Zeditor 深入验证与性能改进记录

日期：2026-10-20。比较基线：`8336306`；分支：`codex/recycle-cloud-docx-safety`。本轮修改尚未提交，未重新生成发行安装包。原有评估见 [产品与用户评估](2026-10-19-product-user-assessment.md)，本文记录其后新增的证据，不覆盖原始测量。

## 1. 结论与验收范围

恢复、保存冲突、回收站、图文云备份和原生 DOCX 已有可运行的完整路径。本轮通过故障注入、真实文件系统、生产前端和隔离 Windows 桌面应用检查，修复了实际发现的并发、恢复、附件引用、图片路径和退出清理问题。不能据此承诺任意故障下零丢失，也不能宣称与成熟编辑器整体性能相当。

| 原评估要求 | 本轮核验与修改 | 当前边界 |
| --- | --- | --- |
| 异常退出后找回草稿、未保存修改 | 在独立原生进程中等待快照持久化后强杀，重启恢复未命名、已有路径及旧格式草稿；逐字比较并确认磁盘原稿未被覆盖 | 快照仍有 900ms 防抖及既有容量/7 天保留限制；不是完整标签会话与时间线持久化 |
| 外部修改不能被自动保存静默覆盖 | 真实第二进程修改文件；手动、自动保存均保留磁盘版本；重载重新读取最新磁盘字节；同进程并发保存按规范化目标串行 | 外部进程仍可能在最后检查与原子替换之间写入，未实现跨进程原子比较交换 |
| 系统回收站恢复 | Windows 原生回收、按 ID 恢复、同名拒绝覆盖和重试已实测；补充中断、坏记录和其他健康记录可见性回归 | 系统可能显示额外确认；macOS/Linux 未实机验收 |
| 云端恢复后图文离线阅读 | 原生 WebDAV 后端对本机 HTTP 服务真实上传/下载；恢复文稿和图片逐字节相等；停掉服务后 WebView 仍能显示图片；WebDAV/S3 后端故障回归通过 | HTTP 服务是隔离夹具；真实云账户、跨设备、服务商兼容性尚未验收；仍限受支持的同级 `.assets` 引用 |
| 真正的 DOCX | 实际菜单写出 OOXML ZIP；检查 CRC、XML、关系、中文、脚注、列表、图片原始字节和未同步的最后一次输入 | 公式保留 TeX、图表保留源码及降级提示；Office/WPS 实际分页和视觉排版尚未验收 |
| 导出准确与基础一致性 | HTML/PDF/DOCX 使用同步后的固定内容快照；实机核验中文和图片；补齐 URL/HTML 实体解码边界 | Mermaid/Markmap 等预览后置增强尚未全部接入各导出格式，不能称为所有格式像素一致 |

## 2. 修复的可靠性问题

所有主要故障修改先用失败回归或实际失败场景定位，再验证修复。

- **并发保存**：两个保存任务可以同时接受同一旧指纹并相继写入。现在同一规范化文件目标串行执行；不同文件仍可并行。删除重复读取后，临时文件同步完成、原子替换之前的最终磁盘指纹检查仍然保留。
- **冲突读取与重载**：焦点重复检查合并；异步读取返回后重新核对标签、路径、文件指纹及最新本地编辑。冲突窗口打开后磁盘再次变化，重载读取最新版本；读取期间本地又编辑时保留修改，要求重新确认。
- **恢复快照**：只提交真正变化的标签，失败不清除待处理标记；未命名草稿清空后删除旧快照。旧格式快照缺少文件指纹时恢复为需另存的草稿，避免把未知磁盘版本当作安全覆盖基线。
- **云任务与附件**：旧任务成功只移除它自身的持久任务；不会擦除排队期间新生成的任务。清理旧版本时保留仍被其他清单引用的资源。无法可靠解码的文稿显式失败，避免发布“完整”但没有附件的备份。S3 签名包含自定义端口的实际 Host。
- **回收记录**：从精确记录的原生 ID 协调中断恢复；不复用任意目录或链接。坏记录独立隔离，不阻止健康项目列表显示；同名目标与恢复源在错误时保留。
- **导出快照**：先同步当前编辑缓冲，再捕获固定的内容、标题和文件路径。选择导出路径时切换标签不会改变正在导出的文稿；取消选择无需完整渲染。
- **本地图片**：HTML 属性实体与 URI 各只解码一次；处理中文、空格、`#`、`&` 和字面 `%`。媒体指令按原始文件路径解析，DOM 图片按 URL 解析，缓存按语义隔离，避免同名 `%20` 文件和空格文件互相混淆。
- **PDF 生命周期**：已完成导出和导出进行中的退出分别用真实进程验证；退出通过浏览器自身的本机 WebSocket 显式关闭本应用创建的 PDF 浏览器，并禁止晚到的任务重新启动浏览器。不依赖标签页存在；实际持有额外引用且标签页为空时的退出回归也已通过。本机连接、读写设置超时。
- **原生 IPC**：实际控制台发现 CSP 阻止 Windows 原生 IPC fetch。补入 Tauri 官方示例中的 `ipc:` 与 `http://ipc.localhost`，原有连接限制继续生效。[Tauri CSP 文档](https://v2.tauri.app/security/csp/)

## 3. 性能结果：按测量范围解释

同机前后比较，中位数；不是竞品对比，也不是 Release 安装版端到端基准。参考 CPU 为 Intel Core i5-8250U（8 逻辑处理器），Node 24.21.0；生产前端浏览器测量使用 Edge 154.0.4258.37。后台负载可能影响结果。

### 3.1 真实文件系统保存

Debug Rust 命令，1 次预热、11 次测量，暖文件缓存，包括编码、临时文件写入/同步、最终指纹检查和替换；不包括 IPC、编辑器和绘制。每次验证准确编码字节与指纹。

| 样稿 | 基线中位数 | 修改后中位数 | 变化 |
| --- | ---: | ---: | ---: |
| UTF-8，约 100 KiB | 29.061ms | 19.504ms | 减少 32.9% |
| UTF-8，约 1 MiB | 234.951ms | 155.875ms | 减少 33.7% |
| UTF-8，约 5 MiB | 1104.996ms | 731.379ms | 减少 33.8% |
| UTF-16LE BOM，UTF-8 等价约 5 MiB | 1827.732ms | 1386.412ms | 减少 24.1% |
| GB18030，UTF-8 等价约 5 MiB | 9752.670ms | 8771.436ms | 减少 10.1% |

主要收益是消除重复全文件读取/哈希。读取、解码及初始指纹的后端代码没有改变，不能把其前后波动算作打开速度提升。GB18030 大文件仍明显慢，保留为后续编码性能剖析对象。

完整数据：[基线 CSV](2026-10-20-document-io-baseline.csv)、[修改后 CSV](2026-10-20-document-io-after.csv)。探针：`src-tauri/src/document_io_probe.rs`。

### 3.2 打开文稿后的前端处理与渲染

超过 64 Ki UTF-16 单元的文本统计延迟到现有 160ms 防抖中执行；界面显示“统计中…”，最终统计最新活动文本。这里只移出首次同步打开的关键路径，没有减少统计的总计算量。

真实 store、即时内存 IPC、无磁盘/绘制的处理阶段：约 94 万 UTF-16 单元由 28.81ms 到 0.106ms，约 472 万由 167.16ms 到 0.078ms。**这些数字不是用户打开文件的总耗时。** 精确文本和最终统计均有断言。

生产 UI 测量从内存 `addTab` 到 rAF 观察到的就绪；排除启动、磁盘、IPC。1 次预热、3 次测量。下表“首显”是帧回调观测代理，不是浏览器 Paint Timing；“完整”检查当前文稿与全部块。

| 模式与样稿 | 基线首显 / 完整 | 修改后首显 / 完整 |
| --- | ---: | ---: |
| 对照，100 KiB 段落 | 236 / 287.2ms | 195 / 233.9ms |
| 对照，500 KiB 段落 | 948.5 / 1005ms | 842.4 / 904.4ms |
| 对照，500 KiB 混合表格 | 7329.7 / 7501.3ms | 4936.6 / 5142.3ms |
| 所见即所得，100 KiB 段落 | 67.8 / 342.3ms | 53.6 / 313.9ms |
| 所见即所得，500 KiB 段落 | 155.9 / 3438.2ms | 125.1 / 3186.1ms |
| 所见即所得，500 KiB 混合表格，9370 块 | 377.8ms / 30 秒内未完成 | 381.1ms / 26935.8ms |

所见即所得保留首次 60 块预算，只让后续批量预算逐步增长并限制上限，减少长文档重复渲染/布局次数。极端密集表格仍需约 27 秒完整就绪，部分运行有 2.3 秒长帧，**尚不满足流畅的大文档编辑目标**。首显基本不变，不能将超时基线换算成精确提升百分比。CSS 可见性实验没有稳定收益，未进入产品代码。

### 3.3 DOCX 与恢复开销

DOCX：Node，1 次预热、5 次测量，包含打包；每次输出验证 OOXML。表格改为线性判断表头；图片最多 4 个并发任务，同一导出重复引用复用、下次导出重新读取，输出顺序保持不变。

| 样稿 | 基线 | 修改后 | 变化 |
| --- | ---: | ---: | ---: |
| 100 行表格 | 27.83ms | 30.92ms | 小样稿无提升 |
| 1000 行表格 | 252.69ms | 121.31ms | 减少 52.0% |
| 5000 行表格 | 1507.39ms | 454.64ms | 减少 69.8% |
| 8 张不同图片，每张夹具延迟 40ms | 385.28ms | 107.47ms | 减少 72.1% |

图片延迟是受控夹具，不能作为真实网络加速承诺。真实解码另测 PNG/JPEG/GIF/BMP 字节保留，WebP/AVIF/SVG 转 PNG，损坏/超尺寸/超大小、网络失败与取消。

真实 React 恢复订阅、内存 IPC：6 个已打开草稿中只编辑 1 个时，每轮快照请求从 6 次降至 1 次，传输 UTF-8 字节从 252653 降到 42128，减少约 83.3%；确认最新输入仍被保存。后端存储的实际落盘开销不包含在此计数中。

## 4. 验证、证据与复现

- 前端：725 项测试通过；ESLint、TypeScript 与生产构建通过。
- Rust：常规 236 项通过、0 失败、6 项默认忽略；其中无标签页且持有额外引用的浏览器退出探针另以独立测试进程运行，1 项通过。fmt 与严格 Clippy（全部 target，警告视为错误）通过。
- Windows 原生：独立应用标识 `com.zeditor.validation20261020`，不使用个人应用配置。真实 Tauri/WebView2、文件系统和 Windows 回收；云端使用回环 HTTP 服务。仅拦截文件选择和消息 UI 的响应，数据读写、恢复、备份与导出命令实际执行。
- 真实菜单 HTML/PDF/DOCX：先在所见即所得输入后立即导出，检查最后输入存在；DOCX 解包检查原图字节，HTML 检查原图 data URL，PDF 检查文件与文本/图片。
- 最终原生套件实际执行 **8 项全部通过，页面异常 0 项**，见 `desktop-final.log` 与 `desktop/results.json`。系统回收场景因额外确认 UI 显式跳过；此前完整运行的 **7 项通过**包含真实系统回收/同名保护/还原，保留于 `desktop-run.log`。这不是宣称最终 9 项无条件全通过。最近重跑的回收等待由测试进程中止，临时原文件保留；桌面工具报截图超时、无法取得输入坐标，因此没有自动取消系统确认策略。
- 最新 PDF 还用 PyMuPDF 提取检查：标题、导出前最后输入均存在，嵌入图片的尺寸与解码像素和原图完全相同。结果：`desktop/export-content-verification.json`。这仍不能替代人工版式验收。
- 独立最终代码复核已检查异步状态、锁、恢复、任务队列、路径与浏览器生命周期，并修复确定的问题。测试数量不等于用户流程覆盖率。

本机日志与 JSON 位于忽略目录 `test-output/reliability/` 和 `test-output/docx-export/`；保留失败与成功记录。测试不读取私人文稿、不连接真实云账户。主要入口：

```powershell

cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets -- -D warnings

# 选择项目已有 Rust 镜像参数时仅作用于当前命令，不改锁文件与全局配置。
# 首先为当前 PowerShell 载入本机 vcvars64.bat 环境。
# 构建下列独立标识；验证脚本会拒绝生产标识的 exe。
```

浏览器脚本需可用的 Playwright；本机通过 `PLAYWRIGHT_MODULE_PATH` 指向已有缓存中的模块，无新增项目依赖。完整路径与实际命令保留在日志。原生回收场景遇到系统确认时需要处理系统窗口，不能把等待确认误报成测试通过。

性能入口：`benchmark-document-state.mjs`、`benchmark-document-render.mjs`、`benchmark-recovery-traffic.mjs`、`benchmark-docx-export.mjs`；图片真实解码入口：`verify-docx-image-reliability.mjs`，均位于 `scripts/`。先启动对应 Vite/preview 服务，具体 URL、轮次与范围见脚本和输出 JSON。

# 编辑功能复审与性能修复（2026-11-02）

基线：`9e0badc`，分支 `codex/editor-writing-improvements`，版本 `0.6.7`。本轮重点复查中文排版、编辑历史、菜单和大文档回归；不代表完成所有平台的完整验收。

## 发现与修复

| 问题 | 复现与原因 | 修复 |
| --- | --- | --- |
| 长行行内语法扫描退化 | 同一行重复 16000 个行内代码或公式，约 64000 字符；原实现每遇到一段语法都重新扫描到行尾 | 已闭合行内代码不再扫描行尾；公式按当前行缓存行尾位置，后续语法复用 |
| 引用/列表内多行公式被改写 | `> $$`、`> \text{中文ABC}`、`> $$` 中的内容会被插入间距；公式识别没有使用已解析的容器内容 | 先识别引用/列表前缀，再判断公式起止，保留公式内部内容 |
| 无实际变化的替换清空重做 | 文稿编辑后撤销，再以原文替换相同范围；所见即所得会先写入历史，清掉重做分支 | 范围内容相同则只更新选区，不建立新历史，不重建文档 |
| 搜索框撤销误改正文 | 搜索框输入后，点击「功能 → 撤销」；菜单按钮抢走焦点，历史命令错误地操作文稿 | 鼠标操作应用菜单时保留原输入焦点，使撤销/重做作用于原输入框或编辑器 |

另对没有方括号的文本跳过整篇 `Int32Array` 配对表分配。原有链接保护仍使用配对表，未改动链接解析规则。

## 性能测量范围

同机 Node 环境，只测 `formatChineseTypography` 计算，排除磁盘、IPC、窗口绘制和 DOM 布局。后台负载、JIT 和输入内容会影响数值，不能把结果解释为整体应用打开速度提升。

| 输入（同一行，64000 字符） | 修复前本轮样本 | 修复后 4 次样本 |
| --- | --- | --- |
| 行内代码 `` `x` `` 加空格，重复 16000 次 | 1591 ms | 36 / 29 / 24 / 26 ms |
| 行内公式 `$x$` 加空格，重复 16000 次 | 1573 ms | 33 / 31 / 25 / 27 ms |

新增的密集语法测试同时验证受保护内容完整、后续正文正常排版，并用宽松的 1000 ms 上限防止平方级扫描回归。它是性能回归哨兵，不是跨机器性能承诺。

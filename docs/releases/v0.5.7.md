# Zeditor v0.5.7

> 发布日期：2026-10-03

本版本聚焦 **AI 功能的正确性与速度**：修复 AI 对话框始终显示未配置服务商的缺陷，让校对失败不再被误报成「未发现问题」，并让整套 AI 链路能在系统代理失效时自动恢复。同时合并本地 Agent 开关与运行时候选、日语 / 韩语界面支持，以及表格列宽拖动修复。

## 更新亮点

### 1. AI 服务商选择修正

- **不再显示未配置的服务商**：候选列表只保留真正配置过的服务商。此前设置页默认的 `openai` 即使从未填写密钥也会被硬塞进列表，并把对话框「钉」在它上面。
- **落到真正生效的服务商**：打开对话框时按「工作区记忆 → 设置默认 → 已配置列表首个」逐级回退，跳过没有凭据的项。
- **按需显示下拉菜单**：只配置一个服务商时隐藏下拉、改为只读文本；配置多个时才提供下拉选择；一个都没配置时显示「未配置」并提示前往设置。
- **凭据摊平**：后端只读取 `AISettings` 顶层字段，从不解析 `provider_profiles`。新增 `resolveAIRequestSettings`，把选定服务商的档案统一摊平到顶层，保证 `provider` / `api_key` / `api_endpoint` / `model` 四者同源——修复「拿某服务商的密钥去打另一服务商默认端点」导致请求全部失败的问题。校对、伴写与聊天（桌面 / 浏览器预览）四条路径统一走这一份逻辑。
- **免密钥模型**：`Ollama` 仅在用户主动选择后才算已配置，避免它在列表里凭空出现、破坏「只配一个就不显示下拉」的预期。

### 2. 校对失败不再被误报为「未发现问题」

- **聚合错误透出真实原因**：此前分块失败只统计个数，报错仅有一句「所有并发校对分块均失败」，看不到状态码。并发与顺序两条路径现在都带上首个分块的下游错误（如 `API错误 (401)`、`429`）。
- **顺序回退兜底复活**：瞬时故障此前被吞成「空结果」，导致专门为限流设计的顺序回退**从未被触发**。现用 `ChunkOutcome` 区分瞬时与确定性失败：前者触发顺序回退，后者（鉴权失败、模型不存在）立即上报、不做无意义重试。
- **部分成功不再要求重跑整篇**：以「有没有一块成功」为唯一失败判据，一部分分块成功时返回已有结果；只有全部失败才报错，且顺序回退全灭时如实报错，不再回落到空数组。

### 3. 校对速度优化

- **并发上限 4 → 8**，并在分块数更少时按实际数量收敛：整篇校对是「多请求、弱交互」的批处理，墙钟时间约等于 `ceil(分块数 / 并发) × 单块耗时`，7 块文档从 2 波降到 1 波。
- **连接池复用**：显式放宽每主机空闲连接数，避免并发请求间反复关闭重建连接（每次重建都要付一次 TLS 握手）。
- **顺序回退按需等待**：仅在上一块失败后等待 120ms，成功路径不再为每个分块固定付一次延迟。
- **修复中文分块被静默截断**：`max_tokens` 原按 `字符数 / 6` 估算，对中文严重偏低（约 1 字 1 token），长分块的 JSON 会被截断——既白跑一整轮生成，又解析不出任何结果。改为 CJK 感知估算（中文 1:1 + 拉丁 4:1，留一倍冗余，2048 封顶）。
- **前端重试收敛**：后端已有每块 3 次退避重试与顺序回退，前端重试由 2 次 / 1000ms 收敛为 1 次 / 500ms。

### 4. 失效系统代理自动绕行

- **自愈**：reqwest 默认读取 `HTTP_PROXY` / `HTTPS_PROXY`，代理未运行时（例如 Clash / V2Ray 退出后环境变量残留）所有 AI 请求都会死在传输层。传输层失败时现在会自动改用 `no_proxy` 直连重试，**仅在直连确实成功后才固化该选择**，因此必须经代理出网的环境行为不变。
- **错误可诊断**：新增 `describe_transport_error` 逐层展开 reqwest 的 source 链。原先 Display 只有一句 `error sending request for url`，真正的 `connection refused` / DNS 失败藏在链里；现在会连同当前代理地址一并呈现。
- **传输层失败归类为瞬时故障**，使顺序回退与直连兜底能够生效；「拉取模型列表」同样具备兜底与可诊断报错。

### 5. 本地 Agent：总开关与每后端启用停用

- **总开关**：新增「AI 未配置时回退本地 AI Agent」。关闭后 AI 未配置直接报错，不再调用本机 CLI。引擎决策整理为「强制 Agent > AI 助手 API > 本地 Agent 后备（总开关）」三分支，校对与伴写保持一致。
- **每后端启用停用**：Claude Code / Codex / OpenCode / Pi 各自新增开关，停用后从 Agent 面板下拉、默认 Agent 下拉与本地桥接候选中全部移除，配置区弱化置灰；缺省启用，旧配置兼容。桥接层读取持久化 `settings.json` 的启用状态（5 秒缓存）以排除停用后端。
- **聊天栏运行时候选**：AI 助手关闭时聊天栏只显示 Agent 运行时（即使上次停留在 API 模式也强制切换）。
- **启动预热**：`agent_probe_backend` 启动预热 + App 启动后台探测，首次调用零等待；Agent 面板下拉只列出已安装且兼容的 CLI，一个都没有时禁用并提示。
- **校对走 Agent 时单次整篇**：本地 Agent 引擎不再按 3200 字符分块导致每块冷启动一次 CLI（4800 字符实测单次 21 秒完成）。

### 6. 界面：日语 / 韩语支持

- 语言库新增 **日本語 / 한국어**（349 条 ×2，回退链：日 / 韩 → 英文 → 原文）。
- 系统语言自动检测：`ja` → 日本語、`ko` → 한국어、`zh-TW` / `zh-CN` → 繁体 / 简体中文、`en` → English，未知语言回退中文。
- 菜单栏「功能」新增语言子菜单（与主题同级，带选中态，切换即时生效并持久化）；菜单栏、标题栏文案接入 `t()`。

### 7. 表格列宽拖动修复

- 列数与首行单元格改用 `table.rows[0].cells`：`thead` / `tbody` 首行都满足 `tr:first-child`，原选择器把列数算成两倍，`colgroup` 多出的 `col` 会让浏览器撑满表格并按比例压缩列宽，导致拖动改不到真实列。
- 拖动起点改为每次重新测量渲染宽度，手柄位置与列宽从此保持一致；缓存恢复按当前列数截断。
- **每列一个右边界手柄**：最右侧边框也能拖动调整最后一列宽度；`ResizeObserver` 跟随布局变化重摆手柄。

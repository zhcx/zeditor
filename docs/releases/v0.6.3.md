# Zeditor v0.6.3

> 发布日期：2026-10-11

这是一个启动体验修复版本：修正应用打开瞬间「预览框先出现，编辑框与资源管理器栏后出现」的顺序错乱。

## 更新日志

### 修复

- **启动时不再逐块出现界面**：此前启动页只在 React 首帧后（双 `requestAnimationFrame`）就淡出，而编辑区是**懒加载**的、Monaco 的首次布局与文字绘制又是**异步**的，预览的 Markdown 却是**同步**渲染的。于是在启动页揭开的那一瞬，预览已有内容，编辑区仍在加载，看起来就是「预览先出现、编辑框后出现」。现在启动页会等到**编辑区首帧真正画出**且**字体就绪**后再淡出，保证揭开时界面已经完整。

- **字体就绪纳入等待**：界面与内容字体会触发二次重排，等待 `document.fonts.ready` 可避免字体替换过程中的跳动被用户看见。

- **编辑区始终有占位骨架**：Monaco 就绪前，编辑区渲染「正在加载编辑器…」占位层（`role="status"`），任何时刻都不再是一片空背景。该占位样式此前已存在但没有任何渲染点，属于死代码，本次接入。

- **超时兜底**：启动页最多等待 3 秒，极端情况下（字体或编辑器始终不就绪）也不会滞留。

### 实现说明

- `appStore` 新增 `editorBootReady` 状态与 `markEditorBootReady()`，由编辑区在 Monaco 完成首帧（下一帧回调）后置位；组件卸载时会取消未执行的回调，避免对已卸载组件更新状态。
- 启动页通过 `useAppStore.subscribe` 订阅该标志，与「字体就绪」共同决定揭开时机。
- 新增 `tests/startupSequence.test.ts`（2 项）锁定等待条件与占位渲染，防止旧的「首帧即淡出」实现复活。

# 文本清理与智能配对设计

## 目标

为 Zeditor 增加两组编辑能力：

1. 通过“格式 → 文本清理”删除行尾空白字符，并将连续空白行压缩为一个。
2. 在编辑器中提供可配置的自动配对、Tab 跳出和空配对 Backspace 删除；代码围栏与已有内容的行内代码中不介入。

## 范围与交互约定

### 文本清理

- 当前编辑器有选区时，只处理选区文本。
- 没有选区时，处理当前文档全文。
- 删除每行末尾的空白字符。
- 将连续空白行压缩为最多一个空白行。
- 不重写文档已有的 LF/CRLF 换行字符；混合换行输入也只修改空白内容本身。
- 不额外规范标题、列表、分隔线或其他 Markdown 结构。
- 清理作为一次编辑操作加入 Monaco 撤销栈；无内容变化时不产生撤销步骤。

### 自动配对

默认开启，可在“设置 → 编辑器”中关闭。关闭后，所有智能配对行为关闭，但文本清理仍可用。

支持的普通配对：

| 开字符 | 闭字符 |
| --- | --- |
| `(` | `)` |
| `[` | `]` |
| `{` | `}` |
| `"` | `"` |
| `'` | `'` |
| `` ` `` | `` ` `` |
| `「` | `」` |
| `『` | `』` |
| `（` | `）` |
| `【` | `】` |
| `《` | `》` |
| `〈` | `〉` |
| `“` | `”` |
| `‘` | `’` |

支持的 Markdown 格式标记：

- 第一次输入 `*`、`_`、`~` 时分别生成 `*|*`、`_|_`、`~|~`。
- 在对应的空配对内再次输入同一标记时，升级为 `**|**`、`__|__`、`~~|~~`，分别覆盖粗体和删除线标记。
- 输入反引号生成 `` `|` ``，用于行内代码。
- 输入 `[` 生成 `[]()`，光标位于方括号内部；Tab 第一次从标签区跳入 URL 区，第二次跳过 URL 闭括号。

键盘规则：

- Tab 只在光标正处于可识别的闭合结构前时跳过闭合字符；其他情况保留 Monaco 默认 Tab 行为。
- 斜杠菜单打开且有候选项时，Tab 仍优先选择斜杠命令。
- 光标位于空配对内部时，Backspace 同时删除开闭字符。
- 空的 `[]()` 链接模板由 Backspace 整体删除。
- 围栏代码块和已有内容的行内代码范围内，自动配对、Tab 跳出和空配对删除均不介入，按 Monaco 默认行为处理。
- 刚刚自动生成的空反引号对允许使用 Tab/Backspace 完成或删除，以便从自动生成的行内代码结构中自然退出。

## 架构

### 纯函数模块

新增 `src/utils/textCleanup.ts`，负责文本清理算法。模块不依赖 React、Zustand 或 Monaco，提供可直接测试的文本转换结果，并保留换行风格。

新增 `src/utils/smartPairs.ts`，负责智能配对决策。模块接收文本、光标位置、按键和启用状态，返回以下决策之一：默认输入、插入闭合结构、跳过闭合结构或删除空配对。模块内部负责识别当前光标是否位于 Markdown 围栏代码块或行内代码范围。

### 编辑器接入

`src/components/Editor/Editor.tsx` 在现有 Monaco `onKeyDown` 处理器中接入 `smartPairs`：

- 斜杠菜单处理继续保持最高优先级。
- 智能配对决策只产生 Monaco 编辑范围和光标位置，不在工具模块中直接操作编辑器。
- 文本替换前后使用 `pushUndoStop()`，使清理、配对升级和删除行为形成清晰的撤销边界。
- “格式 → 文本清理”通过现有 `EditorController` 读取选区、替换文本并恢复选区/光标。

### 设置与菜单

`src/stores/appStore.ts` 在 `Settings.editor` 增加可选的 `smart_pairs?: boolean` 开关，默认开启，并在 `normalizeSettings` 中为旧配置补默认值。

`src/components/Settings/SettingsPanel.tsx` 在编辑器设置页增加“启用自动配对与 Tab 跳出”开关。

`src/components/MenuBar/MenuBar.tsx` 增加“格式”顶层菜单及“文本清理”操作。

## 数据流与边界

1. 用户在编辑器中按键。
2. Monaco 事件处理器将当前文档、光标位置、按键和设置交给 `smartPairs`。
3. 决策为默认输入时交由 Monaco；其他决策由编辑器执行相应文本替换和光标移动。
4. 文本变化继续通过既有 `onDidChangeModelContent` 同步到当前标签页和自动保存链路。
5. 菜单清理使用同一编辑器控制器；没有编辑器实例时静默返回。

文本清理不跳过代码块，因为用户明确要求删除行尾空白与合并空白行，且该操作不涉及 Markdown 结构重排。自动配对的代码区域限制只作用于键盘输入行为。

## 测试与验收

新增 `tests/textCleanup.test.ts`，覆盖：

- 行尾空格、Tab 和其他行尾空白的删除。
- 连续空白行压缩为一个空白行。
- 单个空白行、空文本、无变化文本。
- LF、CRLF 以及混合换行输入中的换行字符保持不变。

新增 `tests/smartPairs.test.ts`，覆盖：

- 所有普通括号、中文括号、弯引号和反引号配对。
- `*`、`_`、`~` 的基础配对与双字符标记升级。
- `[]()` 链接模板及 Tab 分段跳出。
- 普通 Tab、关闭设置、斜杠菜单优先级。
- 空配对 Backspace 和空链接模板删除。
- 围栏代码块、已有内容的行内代码和自动生成空反引号对的边界行为。

完成实现后执行：

```text
npm test
npm run lint
npm run build
```

验收要求是新增单元测试和现有测试全部通过，TypeScript 构建无错误，ESLint 无错误，并通过代码检查确认菜单、设置和 Monaco 事件均已接线。
